# 社群对话覆盖审计 · 2026-10-16

审计对象：当前工作区规则包 `3.2.0|2d37701105fe`。本次只审查与运行现有代码，没有修改生产对话规则或显示逻辑。

**结论：通用提示不能代表原攻略没有答案。当前主要问题是旧攻略衍生数据不完整、只导入既有映射，以及显示过滤与分支模型过粗。已保存原文能为当前缺失的96个场景中的93个提供明示等级的对话记录。另发现构建阶段会错误去重回答序列。**

## 范围与方法

- 枚举全部19个非剧情社群、目标RANK2–10，共171个升级场景；分别运行默认／朋友和恋人路线，共342个组合。数字是场景库存，不是一份计划里通用提示的出现频率。
- 直接调用已有编译生产类的 `DialogueHint`，检查场景、升级、可能不升级、确定不升级、玩家报告卡级等API；342个组合的4项行为检查全部符合现有逻辑。未进行游戏内实测，未重新运行Gradle。
- 核对75个已有映射，以及原3DM p2–p11、p42、游民星空对应页面中的逐日文本。早半段记录73条，晚半段95条；排除等级误标等歧义后，原文覆盖167个不同目标等级，与已有映射合并为168个。
- 3DM与游民星空是同一攻略及其转载，不能当作两份独立游戏验证。中文原文只证明攻略写了什么，不证明官方逐字文本、数字注记含义、完整分支或所有并列最优答案。
- 对照固定Reload来源aqiu的加点与恋爱资格记录，不把英文选项序号当成中文游戏已验证序号，也没有自行翻译补造中文选项。
- RANK1解锁提示另查现有how-to；剧情社群、普通邀约、羁绊剧情、主线选择不计入171。映射文件中的19条未绑定记录混有这些类型，不能一律塞入升级场景。

## 正确性问题

### 回答序列被去重

代码位置：[build_p3r_rules.py](../../rules/build/build_p3r_rules.py:1260)。构建器把同一等级的回答当作集合：

```python
for frag in frags:
    if frag not in bucket:
        bucket.append(frag)
```

实际影响17个场景、13个社群，删除24条重复片段。例子：正义R7“第2项／第2项”变成一次；战车R6“第2项／第2项／那你的膝盖怎么办”丢掉一次回答；恋爱R5“四次任意，然后抱歉”被压成“一次任意，然后抱歉”。应保存有序提问／回答，去重完整来源记录，而非序列内部的字符串。

### 序号过滤与友情策略

- 15个场景带序号，11个过滤后没有具体答案；原中文攻略能给其中许多场景恢复字面选项。只要有明确中文文本，就不必要求用户猜“让对方开心”。力量R7还存在衍生“第1项”与原文“开一个吧（3）”的数字冲突，不能把括号数字武断解释为已验证的选项编号。
- 当前RANK≥8且未显式标恋爱的友情场景会整体隐藏，遮住12个已有映射，其中7个确实有具体文字。需要每个问题的路线条件，保留安全问答、只排除不适用的告白；直接移除保护会误导玩家。
- `avoid`已存具体禁选答案时，App也应能像Widget一样明确展示。女教皇R9目前是可直接定位的例子。

### 有文本也未必足以取得模型里的最佳收益

在aqiu有正加点记录的R3–R9独立场景共109个，其中73个当前没有对话，另2个只写任意（女教皇R8、力量R9）。模型仍按最佳回答的保守数值推演，缺少指导会让玩家实际收益落后于预测。女教皇R5只显示第三问，却按整场最佳35点估计。

固定攻略可能依赖既有面具、魅力和好感余量而省略选项，不能把它当成任意中途存档的通用最优策略。恋爱资格有些回答本身加0点（女教皇R7），不能只根据音符挑选；友情与恋人路线的加点相同也不表示选项相同。英文来源给的是一种最佳回答见证，未穷举所有同分选项，因此不同中文表述不能直接判错。

## 剩余缺口与范围边界

- 女教皇R2：有疑似对应中文片段，无明示等级；需独立事件识别。该场景的点数用于R3，而R3门槛为0，因此目前主要影响指导完整性。
- 太阳R3：两份同源中文原文把9/27与10/11都标成RANK2；10/11有“我不知道／别说话了”，但需核实等级。太阳无需累积好感即可逐次升级，不能据此假称所有回答完全等价。
- 恶魔R10：未找到明确推荐选项；已达终级，无后续好感门槛。缺原文不能自动当作任意。
- 解锁how-to已经提供正义三次搭话、塔点单和月亮答题等中文选项；力量解锁的具体选择也存在unlock.noteZh。它们属于解锁／次要说话人，不能错绑到当次主社群的升级问答。
- 映射文件还保留19条未绑定记录，含邀约、剧情、羁绊剧情及上述女教皇片段；这次没有把这些场景假装成已覆盖的RANK问答。

## 建议修复顺序与验证

1. 修复有序回答去重，加入重复回答与条件分支的保序检查。
2. 从已有原中文攻略补齐93个可绑定缺失场景，同时恢复序号场景的中文文本和被截断的整场问答；保留原有已核实修订，明示来源可信度。
3. 用“场景→路线条件→问题顺序→可选推荐答案／任意／禁选”表达数据，替代混合自然语言字符串与RANK≥8整体屏蔽。
4. 区分未覆盖、已知任意、仅知禁选和当前路线未知；App与Widget使用一致的具体信息。
5. 覆盖测试按全部社群／目标等级检查来源状态、顺序、分支与模型收益假设；目前的旧版字节一致测试和界面一致测试不能检查事实完整性。

本轮未修改生产代码，因此没有新APK、也没有重新宣称原有927项测试验证了这些修复。342种场景路线组合只验证现状；每种组合额外运行升级、不确定不升级、确定不升级、报告卡级4种行为。完整原始结果位于本工作区 `qa_out/dialogue_audit/`，紧凑的可追溯数据已保存到 [dialogue_coverage_2026-10-16.json](dialogue_coverage_2026-10-16.json)。
